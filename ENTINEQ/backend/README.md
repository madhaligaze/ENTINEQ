# ENTINEQ / backend

**Бэкенд публичного приложения ENTINEQ (powered by Claude).** Тонкий по замыслу: проверяет ввод, ставит cookie входа и пересылает запросы и чат в бэкенд [ENTINEQ_AGENT](../../ENTINEQ_AGENT/backend) по внутреннему каналу. Своих ключей Anthropic и базы данных здесь **нет**: аккаунты, лимиты и деньги живут только в ядре, поэтому даже полный взлом этого сервиса ничего не даёт. Страниц тоже нет - их отдаёт [frontend](../frontend).

```
frontend ENTINEQ ──/api, /ws──▶ этот бэкенд ──секрет + токен пользователя──▶ бэкенд ENTINEQ_AGENT ──▶ Claude
```

Что это даёт безопасности:
- В браузер **не попадают** ни секрет, ни токен сессии: токен лежит в `httpOnly`-cookie, а секрет добавляет только этот сервис.
- Права выше публичных получить нельзя: ядро через внутренний канал выдаёт только публичные (чат без инструментов), а владелец и доверенные через него не входят вовсе.
- Секрет принимается ядром только в заголовке, никогда в адресе.
- Ответы ядра проверяются на лету по контракту; при расхождении версий пользователь видит спокойное «Сервис временно недоступен», а в логах - причина.

## Адреса

| Путь | Назначение |
|---|---|
| `POST /api/auth/register`, `/api/auth/login`, `/api/auth/logout` | Регистрация по приглашению, вход, выход (cookie `entineq_session`). |
| `GET /api/me`, `/api/conversations`, `/api/conversations/:id/messages` | Профиль и лимиты, список и история диалогов. |
| `GET /ws` | Чат по WebSocket (прокладка к ядру). |
| `/healthz` | Процесс жив (по нему Railway решает, что деплой удался); от ядра не зависит. |
| `/readyz` | Видит ли бэкенд ядро, принято ли секрет, совпадает ли версия контракта. |

Всё остальное - одинаковый JSON `404`.

### Диагностика связки: `/readyz`

| Ответ | Что значит и что делать |
|---|---|
| `200 {"ok":true}` | Ядро видно, секрет принят, версии совместимы. |
| `503 upstream_unavailable` | Ядро не отвечает: проверьте `AGENT_BASE_URL` и что бэкенд ENTINEQ_AGENT запущен. |
| `503 upstream_misconfigured` | Ядро отклонило секрет: `INTERNAL_API_SECRET` в двух бэкендах не совпадает. |
| `503 contract_mismatch` | Версии несовместимы (одно из приложений старше): обновите оба проекта. |

## Переменные окружения

Полный список - в [`.env.example`](.env.example). Главное:

| Переменная | Обязательна | Назначение |
|---|---|---|
| `AGENT_BASE_URL` | да | Адрес бэкенда ENTINEQ_AGENT: только сервис, без пути. В production - `https://` (исключения: `*.railway.internal`, `localhost`, имена без точки). |
| `INTERNAL_API_SECRET` | да | **Тот же**, что в бэкенде ENTINEQ_AGENT, ≥ 32 символов (`pnpm gen:secret`). |
| `ALLOWED_ORIGINS` | в production | Публичный адрес **фронтенда** (`https://…`), через запятую - несколько. Защита от запросов с чужих сайтов. |
| `PORT` | нет | В Railway задайте `8080` явно: на него ссылается фронтенд. |

## Запуск локально

Сначала запустите бэкенд ENTINEQ_AGENT (порт 8080), затем:

```bash
pnpm install
cp .env.example .env     # AGENT_BASE_URL=http://localhost:8080 и тот же секрет, что у ядра
pnpm dev                 # http://localhost:8081
```

Интерфейс - в [frontend](../frontend) (`pnpm dev`, http://localhost:3001). Нужен код приглашения: интерфейс ENTINEQ_AGENT → Админка → «Приглашения».

## Проверка

```bash
pnpm typecheck
pnpm test        # 54 теста с поддельным ядром, которое умеет «ломаться» (недоступность, неверный секрет, несовместимая версия, обрывы)
```

## Деплой в Railway

1. Залейте содержимое этой папки в отдельный репозиторий GitHub.
2. Railway → в том же проекте, где ядро: **+ New → GitHub Repo**. Сборка по `Dockerfile`, проверка здоровья - из `railway.json`.
3. **Variables**:
   - `AGENT_BASE_URL` = `http://${{entineq-agent-backend.RAILWAY_PRIVATE_DOMAIN}}:${{entineq-agent-backend.PORT}}`;
   - `INTERNAL_API_SECRET` = то же значение, что в бэкенде ENTINEQ_AGENT;
   - `ALLOWED_ORIGINS` = `https://${{entineq-frontend.RAILWAY_PUBLIC_DOMAIN}}`;
   - `PORT` = `8080`.
4. Публичный домен бэкенду **не нужен**: фронтенд обращается к нему по внутренней сети.
5. Проверьте `/readyz` - например, из консоли фронтенда или временно включив домен.

Полная таблица переменных всех пяти сервисов - в [общем README](../../README.md).

## Структура

```
src/
  server.ts        запуск, проверка связки с ядром, корректная остановка
  app.ts           сборка Fastify: заголовки безопасности, ошибки, /healthz, /readyz
  config.ts        переменные окружения с проверкой (Zod)
  contract.ts      как этот проект ждёт ответы ядра (проверяются на лету - защита от расхождения версий)
  core-client.ts   клиент внутреннего API ядра (секрет добавляется только здесь)
  routes/api.ts    вход, регистрация, выход, профиль, диалоги
  routes/ws.ts     прокладка WebSocket «браузер ↔ ядро»
test/              тесты
```
