# ENTINEQ (powered by Claude)

**Публичное приложение для всех остальных пользователей.** Чат с Claude: вход и регистрация по приглашению, история диалогов, потоковый ответ, индикатор лимита сессии с таймером.

У него **нет** ни ключа Anthropic, ни базы данных. Его сервер только проверяет ввод, ставит cookie и пересылает запросы в ядро [ENTINEQ_AGENT](../ENTINEQ_AGENT) по внутреннему каналу. Всё, что требует доверия, — аккаунты, лимиты, ключ — живёт там.

```
Браузер ──HTTPS/WebSocket──▶ ENTINEQ (этот проект) ──секрет + токен пользователя──▶ ENTINEQ_AGENT ──▶ Claude
```

Что это даёт безопасности:
- Из браузера **не видно** ни секрета, ни токена сессии: токен лежит в `httpOnly`-cookie, а секрет добавляет только сервер.
- Публичный адрес **не пробрасывает** админский и внутренний API ядра (проверено тестами).
- Даже при полном взломе этого приложения права выше публичных получить нельзя: ядро через внутреннюю дверь выдаёт только публичные (чат без инструментов), а владелец и доверенные через неё не входят вовсе.
- Секрет принимается ядром только в заголовке, никогда в адресе.

## Что умеет

- Регистрация **только по коду приглашения** (его создаёт владелец в админке ядра; код одноразовый). Вход, выход.
- Чат с потоковым ответом, история диалогов, продолжение диалога после перезагрузки.
- **Лимит сессии с таймером** и месячный лимит: сколько потрачено, сколько осталось, когда сбросится; при исчерпании — блокировка до сброса.
- Тёмная и светлая тема (по настройке системы), работает на телефоне.
- Защита: проверка Origin (CSRF и перехват WebSocket), строгая политика безопасности страницы (CSP, без инлайн-скриптов), ограничение частоты входов и открытий чата, вывод сообщений только как текст (XSS невозможен).

Терминала и инструментов агента здесь нет — это намеренно, до появления изоляции в ядре.

## Переменные окружения

| Переменная | Обязательна | Назначение |
|---|---|---|
| `AGENT_BASE_URL` | да | Адрес ядра: только сайт, без пути (`https://entineq-agent-production.up.railway.app`). В production — `https://` (исключения: `localhost`, `*.railway.internal`, имена без точки). |
| `INTERNAL_API_SECRET` | да | **Тот же**, что в ENTINEQ_AGENT, ≥ 32 символов. |
| `PORT` | нет | Railway задаёт сам. Локально ядро занимает 8080, поэтому здесь `PORT=8081`. |

Остальное (`RATE_LIMIT_*`, `TRUST_PROXY_HOPS`, `COOKIE_SECURE`…) — в [`.env.example`](.env.example).

## Запуск локально

Сначала запустите ядро (`pnpm dev` в ENTINEQ_AGENT, порт 8080), затем:

```bash
pnpm install
cp .env.example .env     # AGENT_BASE_URL=http://localhost:8080 и тот же секрет, что у ядра
PORT=8081 pnpm dev       # http://localhost:8081
```

PowerShell: `$env:PORT=8081; pnpm dev`. Либо впишите `PORT=8081` в `.env`.

Нужен код приглашения: откройте ядро (`http://localhost:8080`) → Админка → «Приглашения».


## Деплой в Railway

Порядок важен: **сначала ядро**, потому что здесь нужен его адрес.

1. Залейте содержимое этой папки в **отдельный** репозиторий GitHub.
2. Railway → **New Project → Deploy from GitHub repo** (это отдельный проект, не тот, где ядро). Сборка по `Dockerfile`, проверка здоровья — из `railway.json`.
3. **Variables**:
   - `AGENT_BASE_URL` = публичный адрес проекта ядра (с `https://`, без слеша и пути);
   - `INTERNAL_API_SECRET` = то же значение, что в ядре.
4. **Settings → Networking → Generate Domain**.
5. Откройте `https://<адрес>/readyz` — должно быть `{"ok":true}`.

### Диагностика связки: `/readyz`

| Ответ | Что значит и что делать |
|---|---|
| `200 {"ok":true}` | Ядро видно, секрет принят, версии совместимы. |
| `503 upstream_unavailable` | Ядро не отвечает: проверьте `AGENT_BASE_URL` и что ядро запущено. |
| `503 upstream_misconfigured` | Ядро отклонило секрет: `INTERNAL_API_SECRET` в двух проектах не совпадает. |
| `503 contract_mismatch` | Версии приложений несовместимы (одно из них старше): обновите оба проекта. |

`/healthz` показывает только, что само приложение живо (по нему Railway решает, удался ли деплой), и от доступности ядра не зависит.

Пользователь при сбое связи видит спокойное «Сервис временно недоступен», а подробности — только в логах. Чат сам переподключается, как только ядро вернётся.

## Структура

```
src/
  server.ts        запуск, проверка связки с ядром, корректная остановка
  app.ts           сборка Fastify: заголовки безопасности, ошибки, /healthz, /readyz
  config.ts        переменные окружения с проверкой (Zod)
  contract.ts      как этот проект ждёт ответы ядра (проверяются на лету — защита от расхождения версий)
  core-client.ts   клиент внутреннего API ядра (секрет добавляется только здесь)
  routes/api.ts    вход, регистрация, выход, профиль, диалоги
  routes/ws.ts     прокладка WebSocket «браузер ↔ ядро»
public/            веб-интерфейс (HTML, CSS, ES-модули без сборки)
test/              тесты
```

Модули `public/js/{api,dom,format,usage,chat}.js` — те же, что в ENTINEQ_AGENT (интерфейс чата у них общий). Правите там — скопируйте сюда.
