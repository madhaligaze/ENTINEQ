# ENTINEQ_AGENT

**Ядро проекта и интерфейс для владельца и доверенных людей.** Работает на [Claude Agent SDK](https://code.claude.com/docs/en/agent-sdk/overview): агент читает и правит файлы и выполняет команды в терминале.

Здесь живут аккаунты, лимиты расходов, учёт трат и ключ Anthropic. Публичное приложение [ENTINEQ](../ENTINEQ) своего ключа и базы не имеет: оно ходит сюда по внутреннему каналу.

```
Владелец и доверенные ─▶ интерфейс ENTINEQ_AGENT ──┐
                                                   ├─▶ ядро ─▶ Claude API
Все остальные ─▶ ENTINEQ ──(внутренний канал + секрет)┘     └─▶ PostgreSQL
```

## Что умеет

- **Две «двери».** Прямая — для владельца и доверенных (вход по паролю, cookie). Внутренняя — для публичного приложения (общий секрет + токен пользователя). Права определяет дверь, а не заявление клиента: через внутреннюю дверь даже аккаунт с высокой ролью получает только публичные права (чат без инструментов).
- **Аккаунты.** Роли `owner`, `trusted`, `public`. Публичные регистрируются только по одноразовому коду-приглашению. Защита: scrypt-хеши, блокировка после 8 неудачных входов на 10 минут, ограничение частоты по IP, проверка Origin (CSRF и перехват WebSocket), строгая политика безопасности страницы (CSP).
- **Лимиты расходов у каждого пользователя** (подробно ниже): окно сессии и месячный бюджет.
- **Учёт расходов.** Токены и стоимость каждого хода пишутся в БД по пользователям и моделям. В админке — отчёт за месяц и выгрузка в CSV, чтобы в конце месяца выставить каждому его сумму.
- **История диалогов** и **сессии агента в Postgres** (диск на Railway сбрасывается при каждом деплое, поэтому транскрипты хранятся в БД и диалог можно продолжить после обновления).
- **Админка** (только владелец): пользователи, лимиты, отключение, смена пароля, приглашения, отчёт по расходам.

## Лимиты: как это работает

Как 5-часовой лимит у подписок Claude, только в долларах и под вашим контролем.

| Лимит | Как действует |
|---|---|
| **Окно сессии** (по умолчанию 5 часов) | Окно открывается **первым сообщением** после окончания прошлого и длится ровно 5 часов (не скользящее). Расход в окне суммируется. Достиг лимита окна — работа блокируется до конца окна, в интерфейсе идёт таймер обратного отсчёта. Следующее сообщение после сброса открывает новое окно. |
| **Месячный бюджет** | Календарный месяц по UTC. Исчерпан — блокировка до 1-го числа. Проверяется раньше окна. |
| **Потолок одного запроса** | `TURN_MAX_BUDGET_USD` (по умолчанию $10), а также остаток окна/месяца: «убежавший» агент не сожжёт больше. |

Значения по умолчанию для **новых** пользователей: публичные — $1 на окно и $10 в месяц, доверенные — $5 на окно и без месячного лимита, владелец — без лимитов. У каждого пользователя их можно изменить в админке (пустое поле = без лимита); значения приглашений — тоже.

> **Про цифры.** Anthropic не публикует лимиты подписок в долларах, и они меняются. Поэтому $1 и $5 — мои ориентиры (примерно «несколько десятков коротких сообщений» и «десяток-другой задач агента» за окно на Opus), а не официальные значения. Подберите свои под реальный расход и вашу цену.
>
> **Про точность.** Суммы берутся из итогов Agent SDK и являются **оценкой**, а не счётом Anthropic (так указано в их документации). Для сверки сравните «Итого» в отчёте с разделом Usage в консоли Anthropic. Пересчёт токенов в доллары делает сам SDK по своей таблице цен.
>
> **Про «начатые заново» итоги.** Если SDK при продолжении диалога не нашёл в транскрипте сохранённых итогов и начал отсчёт с нуля, ENTINEQ это распознаёт (по токенам самого вызова) и учитывает ход целиком, а в логах появляется предупреждение «итоги SDK начались заново».

## Уровни доверия и что делает агент

| Кто | Инструменты | Где работает |
|---|---|---|
| Владелец, доверенные (прямая дверь) | Терминал (`Bash`), чтение/правка файлов, поиск, веб | В рабочей папке пользователя внутри контейнера ядра |
| Публичные (внутренняя дверь) | **Никаких** — только чат | — |

Процесс агента получает окружение **без** секретов ядра (`DATABASE_URL`, `INTERNAL_API_SECRET`, `OWNER_*`, всё, что похоже на токены и пароли). Ключ Anthropic ему всё же нужен для работы.

> **Важное ограничение.** Команды доверенных выполняются **в контейнере ядра**, рядом с ключом Anthropic, и доверенный человек теоретически может его прочитать. Поэтому доверенными делайте только тех, кому вы доверяете. Терминал публичным пользователям не выдаётся намеренно: он появится вместе с изоляцией (отдельный контейнер на пользователя, без ключей внутри, исходящий трафик по белому списку). Это следующий этап.

## Переменные окружения

Полный список с пояснениями — в [`.env.example`](.env.example). Главное:

| Переменная | Обязательна | Назначение |
|---|---|---|
| `INTERNAL_API_SECRET` | да | Общий секрет с ENTINEQ, ≥ 32 символов (`pnpm gen:secret`). |
| `ANTHROPIC_API_KEY` | да* | Ключ Anthropic. *Не нужен при `AGENT_RUNNER=fake`. |
| `OWNER_EMAIL`, `OWNER_PASSWORD` | на первый запуск | Создают владельца, если его ещё нет. После первого входа пароль из переменных можно убрать. |
| `DATABASE_URL` | в production | PostgreSQL. Локально можно не задавать (встроенная БД). |
| `AGENT_MODEL`, `PUBLIC_AGENT_MODEL` | нет | Модели (по умолчанию `claude-opus-5-5`). Для публичных `claude-sonnet-5-5` вдвое дешевле. |
| `PORT` | нет | Railway задаёт сам. |

Приложение при старте проверяет конфигурацию и при ошибке сразу пишет понятную причину.

## Запуск локально

```bash
pnpm install
cp .env.example .env     # впишите ANTHROPIC_API_KEY, OWNER_EMAIL и OWNER_PASSWORD
pnpm dev                 # http://localhost:8080 (встроенная БД, перезапуск при правках)
```

- Без ключа и без расходов: добавьте в `.env` строку `AGENT_RUNNER=fake` — вместо Claude отвечает заглушка (эхо).
- С настоящим Postgres: `pnpm db:up` и `DATABASE_URL=postgres://entineq:entineq@localhost:5432/entineq`.
- Боевая сборка: `pnpm build && pnpm start`.
- Вся связка в контейнерах одной командой — из корня проекта: `docker compose up --build` (см. корневой README).

В Chrome `Secure`-cookie по `http://localhost` принимается (проверено), а Safari может её не принять — при локальном запуске боевого режима тогда задайте `COOKIE_SECURE=false`.

## Проверка

```bash
pnpm typecheck
pnpm test                                  # 159 тестов на встроенной БД (~30 с)
TEST_DATABASE_URL=postgres://postgres@localhost:5432/postgres pnpm test   # тот же набор на настоящем Postgres
pnpm smoke:live -- --yes                   # живая проверка с настоящим Claude (тратит несколько центов)
```

`smoke:live` проверяет то, что нельзя проверить без настоящего API: ответ и потоковые события, продолжение диалога (resume), накопительные ли итоги расхода, сохранение транскрипта в Postgres и продолжение диалога «в новом контейнере». **Запустите его один раз перед первым боевым использованием.**

## Деплой в Railway

1. Залейте содержимое этой папки в отдельный репозиторий GitHub (в корень).
2. Railway → **New Project → Deploy from GitHub repo**. Сборка пойдёт по `Dockerfile`, настройки (проверка здоровья `/healthz`, одна реплика) подхватятся из `railway.json`.
3. В этом же проекте: **+ New → Database → Add PostgreSQL**.
4. Вкладка **Variables** сервиса ядра:
   - `DATABASE_URL` = `${{Postgres.DATABASE_URL}}` (ссылка на сервис базы; имя сервиса может отличаться);
   - `ANTHROPIC_API_KEY`;
   - `INTERNAL_API_SECRET` — сгенерируйте `pnpm gen:secret` и **сохраните**: то же значение пойдёт в публичный проект;
   - `OWNER_EMAIL`, `OWNER_PASSWORD`.
5. **Settings → Networking → Generate Domain** — запишите адрес (понадобится публичному приложению).
6. Откройте адрес, войдите как владелец → вкладка **Админка**.

Дальше: деплой публичного приложения (см. [его README](../ENTINEQ/README.md)), затем в админке создайте приглашения и раздайте друзьям.

Заметки:
- **Одна реплика.** Блокировки одновременных запросов хранятся в памяти процесса, поэтому `numReplicas` = 1 (уже в `railway.json`).
- **Файлы агента** (рабочие папки в `/data`) при деплое пропадают. Чтобы они сохранялись, добавьте Volume с путём `/data` и переменную `RAILWAY_RUN_UID=0` (образ работает не от root, а Railway монтирует тома от root).
- **Миграции БД** выполняются автоматически при старте.
- **БД снаружи Railway** (по публичному адресу): добавьте `DATABASE_SSL=true`.

## Структура

```
src/
  server.ts          запуск: конфиг → БД → миграции → владелец → сервер → корректная остановка
  app.ts             сборка Fastify: заголовки безопасности, ошибки, маршруты
  config.ts          переменные окружения с проверкой (Zod)
  db/                схема Drizzle и подключение (pg в проде, PGlite для разработки и тестов)
  auth/              пароли (scrypt), токены, сервис аккаунтов и приглашений
  chat/service.ts    ход диалога: лимиты → агент → сохранение → учёт расходов
  usage/ledger.ts    окно сессии, месячный бюджет, расход за ход из итогов SDK
  agent/             права по уровням доверия, адаптер Agent SDK, заглушка, хранилище сессий в Postgres
  routes/            прямая дверь, внутренняя дверь, админка, чат (REST и WebSocket)
public/              веб-интерфейс (HTML, CSS, ES-модули без сборки)
drizzle/             SQL-миграции (генерируются: pnpm db:generate)
test/                тесты
scripts/live-smoke.ts  живая проверка с настоящим Claude
```

Изменили схему БД (`src/db/schema.ts`) → `pnpm db:generate` → закоммитьте новый файл из `drizzle/`.
