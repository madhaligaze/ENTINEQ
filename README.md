# ENTINEQ

Продукт на [Claude Agent SDK](https://code.claude.com/docs/en/agent-sdk/overview) из **двух самостоятельных приложений**. Каждое — отдельный проект: свой `Dockerfile`, свои pnpm-команды, свой репозиторий на GitHub и свой проект в Railway. Связаны только через переменные окружения.

| Папка | Что это | Роль | Ключ Anthropic и БД |
|---|---|---|---|
| [`ENTINEQ_AGENT/`](ENTINEQ_AGENT) | Ядро + интерфейс для владельца и доверенных | бэкенд, аккаунты, лимиты, учёт расходов | **есть, только здесь** |
| [`ENTINEQ/`](ENTINEQ) | «ENTINEQ powered by Claude» — публичное приложение | фронтенд-витрина | нет |

```
                          ┌───────────────────────────────────────────┐
Владелец, доверенные ───▶ │ ENTINEQ_AGENT                              │
                          │  аккаунты · лимиты · учёт · агент · БД     │──▶ Claude API
Публичные ──▶ ENTINEQ ──▶ │  /internal/*  (секрет + токен пользователя)│
                          └───────────────────────────────────────────┘
```

Подробности — в README каждого проекта: [ENTINEQ_AGENT](ENTINEQ_AGENT/README.md), [ENTINEQ](ENTINEQ/README.md).

## Как они связаны (переменные)

| | ENTINEQ_AGENT | ENTINEQ |
|---|---|---|
| Ключ Anthropic | `ANTHROPIC_API_KEY` | — |
| Общий секрет | `INTERNAL_API_SECRET` | `INTERNAL_API_SECRET` (**то же значение**) |
| Адрес друг друга | — | `AGENT_BASE_URL` = публичный адрес ядра |
| База данных | `DATABASE_URL` (PostgreSQL) | — |

## Порядок запуска в Railway

1. Репозиторий `entineq-agent` (содержимое `ENTINEQ_AGENT/`) → проект Railway + сервис PostgreSQL → переменные → домен. Войти владельцем.
2. Репозиторий `entineq` (содержимое `ENTINEQ/`) → **другой** проект Railway → `AGENT_BASE_URL` и тот же секрет → домен. Проверить `/readyz`.
3. В админке ядра создать приглашения и раздать друзьям.

Пошагово — в README ядра (раздел «Деплой в Railway») и публичного приложения.

## Локально одной командой

```bash
docker compose up --build
```

Ядро — http://localhost:8080 (владелец `owner@example.com` / `owner-password-123`), публичное — http://localhost:8081. По умолчанию отвечает заглушка вместо Claude; для настоящего создайте рядом файл `.env` с `AGENT_RUNNER=claude` и `ANTHROPIC_API_KEY=…`. Этот файл `docker-compose.yml` нужен только для локальной проверки и в репозитории не публикуется.

| то же для всей связки (регистрация, чат, лимит и таймер, отключение пользователя, падение и возврат ядра, утечки секретов, телефон, CSP) | 67 из 67 |
| Сборка образов Docker и запуск связки в контейнерах (не от root, бинарник SDK под Linux запускается, перезапуск ядра и самой БД посреди работы) | 13 из 13 |

**Не проверено без вашего участия:** запросы к настоящему Claude (в проверках вместо него заглушка) и реальный деплой в Railway. Живую проверку SDK запустите один раз: `pnpm smoke:live -- --yes` в `ENTINEQ_AGENT` (тратит несколько центов).

Папка `e2e/` — сквозные тесты на Playwright (запускаются вне репозиториев, чтобы не тянуть его в проекты):

```bash
node e2e/core.e2e.cjs      # интерфейс ядра
node e2e/full.e2e.cjs      # вся связка
node e2e/compose.e2e.cjs   # связка в контейнерах (после docker compose up)
```

Им нужны собранные проекты (`pnpm build`), PostgreSQL на порту 54329 и Playwright, установленный глобально.
